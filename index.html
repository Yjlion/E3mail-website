Email that is end-to-end encrypted,
and honest about when it isn't.

e3mail is a desktop and mobile mail client with classic email functionality. It speaks IMAP and POP3, encrypts with OpenPGP through RNP, learns keys with Autocrypt, and never lets message content touch the network.

How it works

e3mail is a ground-up port of eeemail. It keeps the ideas and drops the Delta Chat engine underneath: the engine is new C++ on Qt, and because it owns its own transport it receives mail over POP3 as well as IMAP.

IMAP and POP3 are transport only

Mail is downloaded, decrypted, stored locally and, by default, removed from the server. The local database is the mailbox. Mail already on the server when e3mail first connected is never deleted, and “keep N days” and “never delete” are both settings.

Opportunistic, and honest about it

e3mail sends an Autocrypt header, learns keys from the ones it receives, and encrypts when every recipient has a key. Otherwise the message goes in cleartext to everyone, and the composer says so before you send. Strict and lenient modes are there too.

Encrypted ≠ verified

A key learned from a header proves continuity, not identity. So “encrypted” and “verified” are separate badges, and every message row shows which one you actually have.

Tags, not folders

Inbox, Sent and Drafts are derived from what a message is. Archive, Trash and Unverified are tags with meaning, and your own tags sit on top. A message can carry several.

Strangers wait

Mail from senders you haven't accepted doesn't reach the inbox. It waits in Unverified until you accept or block the sender, with a deadline you can see. Exactly one thing deletes mail on a timer, and it is Trash.

Content never reaches the network

HTML is re-emitted through a tag whitelist that drops every remote reference and counts what it removed. The renderer's network manager refuses every request. There is no web engine, scripts cannot run, and a link opens only after you've seen where it goes.

What it looks like

Rendered offscreen from a fixture mailbox, never from a real one. The fixture is built by real accounts exchanging real, encrypted mail through an in-process mail server.

The interface is in English, German, French, Spanish, Simplified Chinese, Japanese, Russian, Polish, Arabic, Hebrew and Yiddish. Everything but English was translated by machine and awaits native review.

Build from source

You need Qt 6.8 or newer (with Qt Linguist's tools), CMake 3.21+, a C++20 compiler, SQLite with FTS5, ICU, and RNP with Botan.

  • Arch: pacman -S qt6-base qt6-declarative qt6-svg qt6-tools icu botan json-c sqlite, then scripts/build-rnp.sh for RNP.
  • Debian / Ubuntu: add libicu-dev and use librnp-dev.
  • macOS: brew install rnp icu4c and set ICU_ROOT=$(brew --prefix icu4c).

e3mail-cli drives the same engine from a terminal. --data-dir points either program at another data directory, and a portable.txt beside the executable keeps data in data/ next to it.

git clone https://github.com/Yjlion/e3mail
cd e3mail
cmake --preset dev
cmake --build --preset dev
ctest --preset dev
./build/dev/src/app/e3mail
